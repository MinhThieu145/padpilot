# ChatVisual — Layer 1 Project Summary

## Name and One-Sentence Pitch
**ChatVisual** — A Windows desktop chat client that lets you ask Claude questions with optional full-screen screenshots, while simultaneously intercepting F1–F9 keys from a USB macro pad so those keys can trigger custom actions instead of their default behavior.

## What It Does
The user sees a single dark-themed, borderless desktop window (always-on-top capable) with a chat history pane and a message input bar. They can type a question, optionally attach a screenshot of the current screen, and send it to Claude. Claude's response streams back and renders with Markdown formatting in the chat pane. Separately, if a specific USB macro pad is plugged in, the app silently intercepts its F1–F9 keystrokes system-wide so those keys no longer reach other applications (the groundwork for binding those keys to custom actions).

## Who It's For and Why
A single developer (the project author) who wants a fast, keyboard-friendly AI assistant overlay while working on Windows — without switching to a browser tab — and who also wants to repurpose a USB macro pad whose firmware cannot be reconfigured. The macro pad sends generic F-key events identical to a regular keyboard; ChatVisual is the layer that differentiates them.

## Platform and Tech Stack
- **OS:** Windows only (Win32 APIs, no cross-platform intent)
- **UI:** WPF (.NET Framework 4.7.2)
- **AI backend:** Anthropic.SDK 5.10.0 (Claude Sonnet 4.6, fixed)
- **Markdown rendering:** MdXaml 1.27.0
- **Code display:** AvalonEdit 6.3.0.90
- **Auth:** `ANTHROPIC_API_KEY` environment variable (no UI)

## Core Features
- **Claude chat** — Multi-turn text conversation with Claude; responses rendered as Markdown.
- **Screenshot attachment** — Captures the full primary display and encodes it as an image in the next API request.
- **Macro pad interception** — Detects the specific USB macro pad (VID_1189) at startup and swallows its F1–F9 keys system-wide, leaving a regular keyboard's F-keys untouched.
- **Window repositioning** — Arrow keys move the borderless window around the screen in 10 px increments.

## Key Vocabulary / Concepts
- **Macro pad** — The specific USB hardware (vendor ID 1189, interface MI_00) whose F-key events the app intercepts. Not configurable from the UI.
- **Low-level keyboard hook (WH_KEYBOARD_LL)** — A Windows system hook that intercepts every keystroke before any app sees it; used here to swallow macro-pad F-keys.
- **Raw Input (WM_INPUT)** — A Windows API that identifies *which physical device* generated a keystroke. Used alongside the hook because the hook alone cannot distinguish macro-pad keys from regular keyboard keys.
- **Key swallowing / injection** — Blocking a key from propagating (swallowing) vs. re-firing it into the system via SendInput (injection). Regular keyboard F-keys are swallowed then re-injected; macro-pad F-keys are just swallowed.
- **Injected event** — A synthetic keystroke generated by software, flagged by the `LLKHF_INJECTED` bit, used to avoid re-intercepting keys the app itself re-fired.

## What This Project Is NOT
- **Not multi-user or networked** — Single local user, no accounts, no sync.
- **Not cross-platform** — Deeply tied to Win32 APIs; Linux/macOS support is out of scope.
- **Not production software** — Explicitly experimental/personal; no installer, no auto-update, no telemetry.
- **Not configurable via UI** — Model, token limits, API key, and target device are all hardcoded or environment-sourced.
- **Not a general macro engine** — The F-key interception is plumbing; no macro binding or scripting UI exists yet.
- **Not commercial** — Personal hobby/learning project.
